# 58商家商业化规则解析助手｜大模型 RAG 垂直原型

## 项目背景

项目灵感来源于本人参与的 58 集团年审审计工作。审计场景中需要高频查阅大量商家**广告投放、会员付费、佣金返点**等商业化公开规则，人工翻阅协议文档效率低、易遗漏。为模拟业务侧"大模型 + 知识库"的落地路径，基于 **Dify** 零代码平台搭建了本 RAG（检索增强生成）原型，实现对商家入驻、广告、会员、佣金规则的快速检索与解析。

> ⚠️ **重要声明**：本项目全部使用互联网**公开可获取**的商家协议、收费规则文档，**未使用任何企业内部审计涉密底稿 / Excel / 内部资料**，仅用于个人技术原型验证与学习。

## 项目目标

- 搭建面向商家商业化业务场景的 RAG 应用，实现规则文档的**语义检索 + 受控问答**
- 完整走通"知识库构建 → Prompt 编排 → 检索调优 → badcase 迭代闭环"的大模型运营流程
- 沉淀一套可复现、可迁移到电商/平台商家场景的 RAG 调优方法论

## 技术方案

整体架构：**用户提问 → 知识库向量检索召回 → 大模型基于召回内容受控生成 → 标注来源并兜底**

1. **知识库构建**：收集 6 份 58 官方公开规则文档（约 9000 字），经文本清洗后上传，采用通用文本分割（分段 ~800 token、重叠 ~200 token），通过 Embedding 模型向量化建立索引。
2. **Prompt 编排**：设计系统提示词约束模型行为边界——必须严格依据检索内容作答、无相关信息直接回复"暂无相关公开规则"、严禁编造、超业务范围拒答，从源头抑制幻觉。
3. **RAG 检索调优**：对比不同 **召回数量（Top K）、相似度阈值（Score Threshold）、检索模式（语义 / 多路召回）**，用召回测试工具量化检索效果，降低噪声、提升命中率。
4. **Badcase 迭代闭环**：构建测试样本集，针对幻觉、召回噪声、召回不足等问题做根因定位，迭代知识库、检索参数与提示词，并回归验证。

## 技术栈与工具

| 环节 | 选型 | 说明 |
|---|---|---|
| 搭建平台 | **Dify**（cloud.dify.ai） | 零代码 Agent / 应用开发平台，个人原型，**未上线生产、未做模型微调训练** |
| 应用类型 | 对话型应用（聊天助手 / Chatbot） | 编排中接入知识库节点 |
| 对话模型（LLM） | `deepseek-ai/DeepSeek-V3` | 通过第三方模型服务（SiliconFlow 硅基流动）接入 |
| 向量模型（Embedding） | `BAAI/bge-m3` | 开源中英文向量模型，用于知识库向量化 |

## RAG 检索调优实录

- **Embedding 模型不可用排查**：文档上传后全部显示"不可用 / 0 分段"，根因为平台 Embedding 模型缺失（沙箱额度用尽）→ 接入第三方模型服务的 `bge-m3` 后重新索引，文档恢复"可用"。
- **相似度阈值过高导致零召回**：初始 Score 阈值设为 0.7，但召回测试显示最相关片段相似度仅 0.56，阈值把全部结果过滤，应用"空答"且无引用 → 将阈值降到 0.2、Top K 从 4 调到 6，恢复正常召回与引用标注。
- **召回噪声与碎片段**：出现裸链接单独成段、20+ 字碎片段被召回等噪声 → 通过文档清洗（去除多余空行、孤立 URL）与调整分段粒度改善；并引入多路召回（语义 + 关键词）提升"扣费/返点/佣金"等精确词命中。
- **调参规律**：阈值↑ → 噪声↓但易漏召回；Top K↑ → 覆盖↑但噪声↑；需结合业务对"准确率 / 召回率"的取舍动态平衡。

## Badcase 迭代闭环

构建 4 条业务测试样本，对输出做质量校验并归类归因，形成 **需求分析 → 优化 → 回归验证** 闭环。详细记录见 [`docs/badcase-notes.md`](docs/badcase-notes.md)。

典型类型：
1. **幻觉问题**：模型编造知识库中不存在的收费数字 → 强化"严禁编造、无信息须明示"约束 + 补充公开文档。
2. **召回噪声**：检索到无关片段答非所问 → 调整阈值、清洗碎片段、引入关键词权重。
3. **召回不足**：知识库有内容却检不到 → 重新分段、补充同义 query。
4. **能力边界**：超出商家入驻/广告/会员/佣金范围的问题直接拒答；回复末尾固定免责声明，设置人工复核兜底。

## 能力迁移

本项目完整沉淀了**规则库/知识库搭建、Embedding 接入、Prompt 编排、RAG 检索调参、badcase 归因与回归闭环**整套实践，可直接迁移到电商平台商家规则、商品政策、内容治理等大模型应用场景。
