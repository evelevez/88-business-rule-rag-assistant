# Badcase 分析记录

- **平台**：Dify（cloud.dify.ai）· 对话型应用 · LLM 初期 Qwen2.5-7B-Instruct，最终 DeepSeek-V3 · Embedding BAAI/bge-m3 · 不做二次训练
- **用途**：记录实测 badcase、根因定位、优化动作与回归结果。面试时按"现象 → 根因 → 优化 → 回归"四段讲。

## 一、测试样本集（4 条）

| # | 测试问题 | 预期来源文档 | 备注 |
|---|---|---|---|
| 1 | 58 商家开通会员后可以发布几条广告？ | 03 网络服务通用条款 / 04 会员套餐 | 考召回精度 |
| 2 | 商家投放广告如何扣费？ | 02 推广用户服务协议 | 考召回相关性 |

## 二、环境/链路类问题（最能体现排障能力）

**问题 0：Embedding 模型不可用，文档全部"不可用 / 0 分段"**

- **现象**：6 份文档上传后卡片全显示"不可用"，部分文档分段数 0/1；知识库页面右上角黄色警告"Embedding 模型不可用"。
- **根因**：Dify 云沙箱自带的免费模型额度（200 条）用尽，没有可用的 Embedding 模型，文本无法向量化。
- **优化动作**：
  1. 接入第三方模型服务（硅基流动 SiliconFlow），使用开源向量模型 BAAI/bge-m3（免费）作为 Embedding；
  2. 同时接入 Qwen/Qwen2.5-7B-Instruct 作为对话模型；
  3. 在"默认模型设置"里把 Embedding / 系统推理模型都切到新模型，文档重新索引。
- **回归结果**：✅ 文档状态全部变绿"可用"，召回测试能返回分段。
- **面试点**：能讲清 RAG 里 Embedding 模型负责"文本→向量"，缺它检索链路根本不成立；以及如何独立接入模型供应商。

## 三、Badcase 实测记录

### Badcase 1：相似度阈值过高 → 应用零召回、空答

- **现象**：预览中问 4 个问题，模型回答含糊（"建议咨询客服"），回答下方没有任何"引用"标签，说明没走知识库。
- **根因**：初始 Score 阈值设为 0.7，但召回测试显示最相关片段相似度仅 0.56，其余 0.46——阈值把全部结果过滤掉了，模型拿不到上下文只能凭空答。
- **优化动作**：
  - Score 阈值 0.7 → 0.2；Top K 4 → 6；
  - 保存并重新发布。
- **回归结果**：回答下方出现"引用"标签、答案基于召回片段作答。
- **面试点**：阈值是"准确率 vs 召回率"的杠杆——过高漏召回、过低进噪声，要用召回测试拿分数分布来定，不能拍脑袋。

### Badcase 2：召回噪声 / 相关性差

- **现象**：问"商家投放广告如何扣费"，召回测试召回 3 段：①"明码标价、严禁不正当价格行为"（0.56）②一个光秃秃的 URL 链接（0.46）③"使用夸张标题，内容与标题严重不符"（0.46，仅 21 字）。全部来自文档 01，本应最相关的 02/04/05 一条没中。
- **根因**：
  - 切片过碎：txt 中多余空行 / 孤立 URL 被切成独立小段，制造噪声；
  - 纯语义检索对"扣费"这种精确词匹配偏弱。
- **优化动作**：
  - 文档清洗：删掉孤立 URL 行、合并多余空行后重传；
  - 检索改多路召回，语义权重 0.7 + 关键词权重 0.3，强化精确词命中；
  - 必要时对 02/04/05 补同义表述。
- **回归结果**：优化后"广告扣费"可召回 02 推广协议相关片段。

### Badcase 3：知识缺失 → 幻觉 / 兜底

- **现象**：问"佣金分成比例是多少"，公开协议里本就没有统一抽成比例（58 是会员费 + 推广费模式），模型容易编造"抽成 15%~30%"之类数字。
- **根因**：知识库缺失该条款；小模型对"禁止编造"指令遵循弱。
- **优化动作**：
  - 系统提示词强化："知识库无对应信息必须回复'暂无相关公开规则'，严禁编造"；
  - 对确有公开信息的点（如会员返点 05 文档）补充材料；无公开信息的点明确走兜底话术。
- **回归结果**：模型改为回复"暂无相关公开规则"而非编数字。
- **面试点**：RAG 不能消灭所有幻觉，要靠 prompt 约束 + 知识补齐 + 人工复核兜底三层防线。

### Badcase 4：超范围提问 → 拒答边界

- **现象 / 验证**：问与商家规则无关的问题（如闲聊、其他平台政策）。
- **预期**：模型按提示词直接拒答。
- **回归结果**：实测 1-2 条，模型正确拒答。

### Badcase 5：生成模型能力不足 → 输出混乱、不遵循指令

- **现象**：初期用免费 Qwen2.5-7B-Instruct，召回链路已通，但回答出现中英文混排（"建议至 the context provided"、"those"）、语句断裂、编号错乱，且不按提示词回复"暂无相关公开规则"。
- **根因**：7B 小模型在塞入多个召回片段后，指令遵循与中文稳定性不足；属生成侧瓶颈，非检索问题。
- **优化动作**：保持检索配置不变，将 LLM 切换为 deepseek-ai/DeepSeek-V3。
- **回归结果**：✅ 输出干净、分点清晰，Q1/Q3 正确兜底"暂无相关公开规则"，Q2/Q4 基于召回片段作答。
- **面试点**：RAG 效果 = 检索质量 × 生成质量；检索修好后还要选指令遵循能力强的生成模型。

## 四、本轮调参结论（最终配置）

| 参数 | 初始值 | 最终值 | 调整原因 |
|---|---|---|---|
| 检索模式 | 语义检索 | 多路召回（语义为主，可调关键词权重） | 提升"扣费/返点"等精确词命中 |
| Top K | 4 | 6 | 文档短、分段小，适当增大覆盖 |
| Score 阈值 | 0.7 | 0.2 | 初始阈值过高导致零召回（实测最高相关分仅 0.56） |
| Embedding | 缺失（不可用） | BAAI/bge-m3 | 修复向量化链路 |
| LLM | gpt-5（额度尽）→ Qwen2.5-7B | DeepSeek-V3 | 7B 小模型输出混乱、指令遵循弱，换 V3 后稳定 |

## 五、闭环与能力边界

- 已完成 **需求分析 → 优化 → 回归验证** 闭环（阈值/模型/文档三类改动均回归）。
- 模型能力边界：仅回答商家入驻、广告、会员、佣金分成范围内问题，超范围拒答。
- 人工复核兜底：回复末尾固定提示"本原型仅基于互联网公开文档，不代表官方业务口径"。
